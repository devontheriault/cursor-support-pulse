# Build contract (shared by every part of the pipeline)

Pipeline: `crawl.py` → `raw/` → `label.py issues|assign` → `out/labels.json` → `build.py` → `out/top_issues.json` → `label.py docs` → `out/doc_matches.json` → `build.py` → `~/Projects/Personal Website/cursor/data.js`.

Python: `.venv/bin/python` (3.14, duckdb 2.0 installed; standard library otherwise). No Anthropic API key exists: LLM calls go through the Claude Code CLI, `claude -p --model haiku --output-format json "<prompt>"` (JSON result in `.result`). Real sample responses are in `sample/` (2 topic lists, 4 topics, the docs sitemap): build and test against them.

## Scope
- Forum categories: Bug Reports (id 6, slug `support/bug-report`) and Help (id 8). Window: threads **created** in the last 90 days before the crawl started (`META.from`..`META.to`).
- Drop pinned threads and threads whose first post is by staff.
- Usernames and names are used only to count distinct users. They never appear in `out/` or `data.js`.

## raw/ (written by crawl.py, read by everything else)
- `raw/lists/{cat}_p{N}.json`: topic-list pages exactly as returned (`/c/{cat}/l/latest.json?page=N`; note `latest` sorts by last activity, so stop on `bumped_at` older than the window, or use `order=created`).
- `raw/topics/{id}.json`: topic JSON exactly as returned by `/t/{id}.json`, except `post_stream.posts` holds **every** post in the thread (the extra posts fetched from `/t/{id}/posts.json?post_ids[]=…` merged in, in `post_number` order).
- `raw/docs_sitemap.xml`: `https://cursor.com/docs/sitemap.xml`.
- `raw/crawl.json`: `{started_at, finished_at|null, window_from, window_to, lists: n, topics: n, errors: [...]}`.
- Useful post fields: `user_id`, `staff`, `created_at`, `post_number`, `cooked` (HTML), `link_counts[].url`, `reactions`, `accepted_answer`. Topic fields: `title`, `tags[].name`, `views`, `like_count`, `participant_count`, `has_accepted_answer`, `category_id`, `pinned`, `discourse_zendesk_plugin_zendesk_id`.

## out/ (git-ignored)
- `out/issues_proposed.json`: `["Agent stops mid-task", ...]` from `label.py issues` (pass 1). The reviewed copy is `out/issues.json` (same shape, always includes `"Other"`).
- `out/labels.json`: `[{"id": 175510, "issue": "<one of out/issues.json>", "sentiment": -0.6}]` from `label.py assign` (pass 2). Sentiment is −1 to 1.
- `out/top_issues.json`: `[{"rank": 1, "issue": "...", "threads": 412, "sample_titles": ["..."]}]`, the top 10 from `build.py`.
- `out/doc_matches.json`: `{"<issue>": {"url": "https://cursor.com/docs/..." | null, "reason": "..."}}` from `label.py docs` (Haiku picks the best page from the sitemap for each top issue, or null).

## data.js (written by build.py, read by the page)
ES module at `~/Projects/Personal Website/cursor/data.js`:
```js
// Generated by cursor-support-pulse/build.py. Do not edit.
export const META = { asOf: '2026-10-23', windowDays: 90, from: '2026-07-25', to: '2026-10-22', categories: ['Bug Reports', 'Help'], repo: 'https://github.com/devontheriault/cursor-support-pulse' };
export const HEADER = { threads: 6123, users: 4810, top10Threads: 2510, top10Share: 0.41, top10Missing: 3 };
// Top 10 by score, rank 1 first. parts are each 0–1 (min-max over all issues except Other); score = their mean.
export const ISSUES = [
  { rank: 1, issue: 'Agent stops mid-task', threads: 412, users: 1530, likes: 380, staffPosts: 96, sentiment: -0.42,
    parts: { frequency: 1, breadth: 0.8, staffCost: 0.7, negativity: 0.6 }, score: 0.78,
    doc: { status: 'linked', url: 'https://cursor.com/docs/agent/overview', linkedShare: 0.25 },
    example: 'https://forum.cursor.com/t/175510' },
];
// doc.status: 'linked' (staff link a /docs or /help page in ≥ 20% of the issue's threads; url = most-linked page),
// 'unlinked' (a matching doc exists but staff rarely link it), 'missing' (no matching doc), 'unknown' (not matched yet).
// Launches: tags first seen ≥ 7 days after the window opens, top 4 by week-0 threads. week 0 = the 7 days from the first tagged thread.
export const LAUNCHES = [
  { tag: 'grok-bot', label: 'Grok Bot', firstSeen: '2026-10-12', weeks: [310, 240, 120, 80, 60] },
];
```
Dates are ISO strings; the page formats them ("Oct 12").
